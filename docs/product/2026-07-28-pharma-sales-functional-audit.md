# Pharma CRM 药企销售条线产品功能审查

审查日期：2026-07-28  
审查目标：先判断现有 CRM 能否支撑药企销售条线日常工作，再决定技术底座与 MCP 建设范围。

> 2026-07-28 实施更新：本文提出的五个 P0 演示闭环已经实现，包括周计划/日历转拜访、拜访简报与任务复访、经理辅导工作台、样品最小闭环以及会议签到与跟进。下文的“当前能力”保留为实施前基线，验收后的操作路径见 `pharma-sales-p0-demo-script.md`。

## 一、结论

当前系统不是“功能数量不够”，而是“功能分布不均、关键流程没有闭环”。

- 客户主数据、建档审批、客户分级、拜访记录、经理评定已经有较好原型。
- 周计划、样品、会议、产品、KAM、目标分析多数停留在数据展示或单点操作。
- 代表无法在一个连续流程里完成“计划今天做什么 → 拜访前准备 → 拜访执行 → 样品/产品沟通 → 后续任务 → 复访”。
- 经理可以审批、评定，但缺少“目标下达 → 过程监控 → 异常发现 → 辅导跟进”的工作台。
- 销售运营缺少周期计划、辖区调整、主数据治理、业务规则配置和销量/处方结果数据。

因此：

> 当前版本适合演示“客户 360 + 拜访记录 + 经理评定 + Agent 辅助”，尚不适合宣传为一套完整的药企销售 CRM。

按日常业务闭环估算，现有产品完成度约为 **50%**。这个数字衡量的是流程能否完成，不是页面或数据表数量。

## 二、按角色审查

### 1. 医药代表的一天

| 工作阶段 | 当前能力 | 判断 | 主要断点 |
|---|---|---|---|
| 查看今日安排 | 有周计划列表 | 不够 | 没有日历、今日任务、地图；页面甚至没有创建周计划入口 |
| 选择拜访客户 | 有 HCP/HCO 列表、分级、辖区 | 基本够 | 缺目标频次、久未拜访、潜力与优先级建议 |
| 拜访前准备 | 有 HCP 360、历史拜访、样品和参会记录 | 基础可用 | 上次承诺、待办、关键产品信息没有聚合成拜访简报 |
| 签到和拜访记录 | 有签到、拜访类型、目的、纪要、产品反馈 | 基础可用 | 计划不能直接转拜访；多人拜访、协访关系较弱 |
| 发放样品 | 可随拜访扣减库存并记录批号 | 演示可用 | 缺资格校验、签收、退回、盘点、损耗、过期和差异处理 |
| 记录结果 | 有 outcome、summary、nextStep | 不闭环 | nextStep 只是文本，不会形成有负责人和截止日期的任务 |
| 拜访后跟进 | 无统一任务中心 | 缺失 | 不能提醒、完成、延期、转交，也不能回链下一次拜访 |
| 查看个人业绩 | 有拜访量、覆盖率等基础指标 | 部分可用 | 缺目标差距、销量/处方结果、行动建议 |

代表侧最关键的问题：**已有拜访记录，但缺少拜访前后两端，最终变成“事后填报系统”。**

### 2. 地区经理的一周

| 工作阶段 | 当前能力 | 判断 | 主要断点 |
|---|---|---|---|
| 制定团队周期目标 | 有 Target 数据模型 | 不够 | 没有 Cycle Plan/Call Plan 工作流和配置界面 |
| 审批代表周计划 | 有提交、批准、驳回 | 半闭环 | 代表端不能创建/编辑计划；审批结果没有形成日程 |
| 查看执行进度 | 有团队/辖区基础分析 | 部分可用 | 看不到计划达成、覆盖缺口、超期跟进、样品异常 |
| 评定拜访质量 | 有待评定列表、有效/无效及原因 | 基础可用 | 缺抽查规则、辅导记录和整改复查 |
| 协访与带教 | 拜访类型含 JOINT | 不够 | 没有协访安排、现场观察、辅导行动项 |
| 团队复盘 | 有 KPI 和趋势 | 不够 | 指标不能下钻为待处理对象，也不能生成行动计划 |

经理侧最关键的问题：**有审批和评价动作，没有统一的“异常—辅导—整改—复查”管理闭环。**

### 3. 销售运营的一个周期

| 工作阶段 | 当前能力 | 判断 | 主要断点 |
|---|---|---|---|
| 组织与辖区 | 有员工、部门、辖区树 | 基础可用 | 缺调整、生效日期、交接和历史版本 |
| 客户主数据 | HCP/HCO 字段丰富，有建档审批 | 较强 | HCP 只支持单一主机构；缺去重、合并、数据变更申请 |
| 客户分级与分配 | 有分级历史、客户分配 | 基础可用 | 缺分级规则、批量调整、覆盖频次联动 |
| 产品管理 | 有产品目录 | 太薄 | 只是目录，没有销售信息、合规资料和拜访内容 |
| 会议活动 | 后端可创建，前端只展示 | 不闭环 | 缺预算、邀请、签到、费用、会后跟进与转化 |
| 样品运营 | 有批次和收发模型 | 不够 | 只有 RECEIVE/DISTRIBUTE，无法完成库存全生命周期 |
| 目标与结果 | 有目标和活动 KPI | 不够 | 没有销量、处方、订单等结果事实，无法做销售达成分析 |
| KAM | 有 KA 标记和负责人 | 缺失 | 没有 Account Plan、目标、策略、战术、里程碑和跨团队任务 |

运营侧最关键的问题：**现有系统能保存客户和活动数据，但还不能配置和驱动一个销售周期。**

## 三、功能之间的衔接审查

### 已经衔接较好的链路

1. 客户建档申请 → 经理审批 → 客户档案。
2. 客户档案 → 分级/分配 → 代表查看。
3. 拜访记录 → 产品反馈/样品扣减 → HCP 360。
4. 拜访提交 → 经理有效性评定 → 基础 KPI。

### 存在明显断点的链路

1. **目标 → 周计划**：目标没有驱动建议拜访对象和频次。
2. **周计划 → 日程 → 拜访**：后端支持创建周计划，但前端没有创建入口，也不能从计划项发起拜访。
3. **拜访结果 → 后续任务 → 复访**：nextStep 只是文本，无法被执行和追踪。
4. **产品 → 拜访内容 → 客户反馈**：产品页是静态目录，无法准备或复用合规沟通内容。
5. **会议 → 客户 → 跟进**：会议参会记录能进入 HCP 360，但没有会前邀请和会后行动。
6. **样品库存 → 发放 → 签收 → 对账**：只有库存查看和拜访扣减，缺少操作及合规闭环。
7. **经理指标 → 异常对象 → 辅导任务**：分析页只能看，不能转成管理动作。
8. **HCO 战略客户 → Account Plan → 执行活动**：只有 KA 标签和负责人，没有战略计划。

## 四、演示版必须补什么

### P0：补齐核心故事线

这些功能决定系统看起来是 CRM，还是一组相互独立的页面。

1. **日历/周计划工作台**
   - 创建、编辑、复制周计划。
   - 从客户 360 加入计划。
   - 计划项直接“开始拜访/记录拜访”。
   - 展示计划完成、未完成、临时拜访。

2. **拜访闭环**
   - 拜访前简报：客户概况、上次沟通、未完成承诺、推荐目标。
   - 拜访记录关联计划项。
   - nextStep 升级为任务：内容、负责人、截止日期、状态。
   - 任务完成后可直接创建复访。

3. **经理工作台**
   - 待批计划、待评拜访、未达覆盖、超期任务、异常签到集中展示。
   - 指标下钻到代表和客户。
   - 评定拜访时可创建辅导行动项并追踪完成。

4. **样品最小闭环**
   - 领用入库、拜访发放、退回、盘点四种操作。
   - 发放时展示库存、批号、有效期和领取记录。
   - 演示版至少加入签收确认和库存差异提示。

5. **会议与客户跟进**
   - 前端创建会议、选择 HCP、记录签到。
   - 会后批量生成跟进任务。
   - HCP 360 展示参会和后续执行结果。

### P1：增强“药企专用”辨识度

1. Cycle Plan：按客户级别定义周期覆盖目标和拜访频次。
2. 合规产品资料：产品话术/材料及版本，关联拜访反馈。
3. Account Plan Lite：战略 HCO 的目标、关键关系人、行动和进度。
4. 销售结果导入：用演示数据导入目标与实际销量，形成活动到结果的分析。
5. HCP 多机构/多科室任职，支持主要任职与其他执业点。

### 暂缓，不阻塞宣传 Demo

- 完整移动离线。
- 合规邮件与远程拜访。
- 费用报销。
- 完整样品法规规则引擎。
- 医学问询、不良事件和产品投诉正式工单。
- 复杂辖区版本、客户主数据合并和外部 MDM。
- SSO/RBAC、PostgreSQL、MCP 审批和审计的生产级建设。

这些不是不重要，而是只有在确认产品主链成立、进入真实客户试点后才值得投入。演示数据必须明确标识为模拟数据。

## 五、建议的演示主线

不要按菜单逐页展示，按一个代表和一个经理的故事演示：

1. 经理下达本周期 A 类客户覆盖要求。
2. Agent 根据目标、历史拜访和未完成任务生成本周计划草稿。
3. 代表调整并提交，经理批准。
4. 代表打开今日安排，查看某 HCP 的拜访前简报。
5. 完成签到，记录产品反馈和样品发放。
6. 系统把后续承诺生成任务，并安排复访。
7. 经理在工作台看到完成情况、异常和待辅导项。
8. Agent 总结团队差距并建议下一步行动。

这条主线既能体现现有系统价值，也能自然说明 WorkBuddy/MCP 的作用；Agent 是在业务闭环上提效，而不是替代缺失的 CRM 产品功能。

## 六、建议执行包

| 工作包 | 产出 | 预估 |
|---|---|---:|
| WP1 计划与日历闭环 | 周计划编辑、日历、计划转拜访、完成状态 | 4–6 人日 |
| WP2 拜访前后闭环 | 拜访简报、结构化任务、复访入口 | 4–6 人日 |
| WP3 经理工作台 | 待办、异常、下钻、辅导行动项 | 4–6 人日 |
| WP4 样品最小闭环 | 领用/发放/退回/盘点、签收确认 | 3–5 人日 |
| WP5 会议跟进闭环 | 创建、邀请/签到、批量跟进 | 3–4 人日 |
| WP6 药企增强与演示数据 | Cycle Plan Lite、Account Plan Lite、销售结果数据 | 5–8 人日 |
| WP7 Agent 串联 | 计划草稿、拜访简报、跟进建议、经理复盘 | 4–6 人日 |

单人顺序开发约 5–7 周；两名熟悉代码的开发并行可压缩到约 3–4 周。这里不包含生产级安全、离线和合规体系建设。

## 七、验收标准

产品功能补齐是否成功，不以新增页面数判断，而以以下任务能否连续完成判断：

1. 代表能从目标出发制定计划，并从计划完成一次拜访。
2. 拜访产生的样品、产品反馈和后续行动都能追踪。
3. 经理能发现一个异常，把它变成辅导动作，并看到处理结果。
4. 一场会议能从创建走到客户跟进。
5. 一个战略 HCO 能看到目标、关键人、行动和进度。
6. Agent 的每项建议都落到现有业务对象，并由人确认后执行。
