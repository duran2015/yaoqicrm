# 销售情报中心与 WorkBuddy Agent 演示脚本

## 演示目标

展示互联网信息如何经过来源追溯和核验，进入代表首页与拜访准备。Agent 不把媒体线索冒充已核验事实，也不把内部情报冒充批准材料。

## CRM 演示

1. 打开 `http://47.116.206.152/pharma/sales-intelligence`。
2. 查看政策、竞品、新闻、疾病知识和产品知识的来源与核验状态。
3. 点击“立即采集”，观察新增、更新、失败统计；重复内容不会重复入库。
4. 在“待核验”中核对竞品原文并通过。
5. 回到代表首页查看“与你相关的新情报”。
6. 打开产品页，对比“市场与知识”和“合规资料”。

## WorkBuddy 对话

### 检索情报

> 帮我查一下安瑞泽最近的医保政策、竞品动态和相关疾病知识。只把已核验内容作为结论，同时列出来源；待核验线索单独放在最后。

预期调用：`search_sales_intelligence`。

### 产品应对卡

> 给我生成安瑞泽的拜访应对卡，区分内部参考信息和可以向医生展示的批准资料。

预期调用：`get_product_battlecard`。已核验事实带来源，待核验线索单列，批准材料带版本和批准编号。

### HCP 拜访准备

> 我要拜访丁伯强医生，结合他的专科、最近拜访、待办、产品情报和批准资料帮我准备。

预期调用：`prepare_hcp_visit`。

### 更新产品情报

> 更新这个产品的互联网情报。

Agent 必须先取得用户确认，再调用 `refresh_product_intelligence`。相同 `idempotencyKey` 重试返回相同操作和采集任务。

## 验收点

- MCP 身份只使用 JWT 绑定员工；
- 普通搜索默认不返回待核验内容；
- 每个关键事实可打开原始来源；
- 产品刷新留下 `McpOperation` 和 `CollectionRun`；
- 采集失败不影响既有数据和其他来源；
- 拜访完成继续使用原有 `complete_hcp_visit` 闭环。
